## 2. 在线 TTS：准确的原始设计

正确路径为：系统 TTS / 在线 TTS 二选一 → 在线分支的“服务信息” → “立即配置” → “第三方 TTS 配置”弹窗 → 取消或保存 → 回到在线页签。填写名称和地址后保存，在线卡片副标题显示服务名，入口显示“已配置 · 编辑”；再进入时回填上次保存的全部五项。

| 顺序 | Make 字段 / 原始默认 | Make 交互 | 当前 Harmony |
|---|---|---|---|
| 1 | 服务名称，空；提示“例如 Azure 语音” | 文本编辑，进入时从已保存对象复制到草稿 | 存在 |
| 2 | 接口地址，空；提示 `https://api.example.com/tts` | 文本编辑 | 存在，但提示改成 URL 模板说明 |
| 3 | API 密钥，空；提示“填入访问密钥” | `type="password"`，应遮蔽输入 | **完全缺失** |
| 4 | 发音人 / 音色，空；提示“例如 xiaoxiao” | 文本编辑，独立于系统音色选择 | **完全缺失** |
| 5 | 音频格式，默认 `mp3` | MP3、WAV、PCM 三个互斥胶囊按钮，点击更新草稿 | **三个按钮及字段状态均缺失** |

Make 的关闭按钮、遮罩和“取消”均丢弃本次未保存草稿；“保存”提交整个五字段对象并关闭。`configured` 的条件是名称与地址去空格后非空，不要求密钥与发音人必填。源码的保存按钮本身没有禁用/校验逻辑，不能把“没有校验”说成完整生产要求，也不能擅自增加密钥必填。

Make 弹窗为底部独立面板，最大宽 364、左右 13、底部 16、圆角 22、背景 `#fffaf4`、边线 0.5 / `rgba(180,166,151,.4)`、阴影 `0 18px 48px rgba(31,27,23,.28)`。头部是云图标、标题、关闭；中间只有五项表单，最大滚动高度 440；**取消/保存是滚动区域外的固定底部栏**。输入框高 42 / 圆角 10 / 字号 13；聚焦边线 1.5 teal；格式按钮间距 8；底部按钮高 44 / 圆角 12 / 间距 10。开关弹层从 y=60 与透明态过渡，spring 380 / damping 34。

当前实现则是“两字段 + 已配置服务列表/选择/编辑/删除”，表单、错误和底部按钮一起滚动，基础高度 324，窗口动画为 NONE；这不等同于原设计。列表是现有业务能力，**不是这份 Make 弹窗的内容**。即使需要保留多服务能力，也不能用它覆盖该五项表单。

**协议边界与设计缺失是两件事。** Make 只定义前端五字段对象，没有发起真实 TTS 请求。当前 Core/Harmony 合同是 GET 模板、原始 header/contentType 等，没有 apiKey/voice/format 的完整保存与请求映射。三字段既没有 UI，也没有对应数据链路；这两层都需要设计和实现。不能因为协议尚未确定就删除设计字段，也不能仅显示字段而让其不参与保存或请求。该缺口不是用户补一份接口文档就能自动消除的 UI 误差。

## 5. Make 原型本身未闭合的行为

以下是来源边界，不是删除设计的理由：

- 完整页“上一章/下一章”、快捷页“上一句/下一句”、系统默认/语言按钮没有业务回调。两种粒度的文字不一致，需要保留并明确生产语义，不能笼统把两者都称已还原。
- 原型的试听只有本地试听状态与波形，没有播放真实音频；原型定时只有选择状态，没有计时终止；后台/常亮仅布尔 state。这些都需要生产端真实接线。
- Make 的 Quick 和 Full 分别持有独立播放、定时与语速 state，切换分支会卸载并重置；音色选择也没有更新 PlaybackModule 中硬编码的“清晰女声”。**不能复制这些状态断裂到应用。** 用户已明确保留原共享动效，应用也应保留同一业务状态。
- 界面 Make 的四个下拉有真实本地选择；主题块、日夜设置、字体块/导入、字号等步进器和“收起”是静态或没有事件处理。应用应保留这些既有真实功能，同时按设计呈现；不能用空点击冒充还原。
- 目录/设置等导航图标在这份 Make 里不是已实现的完整目标页，旧 imports 中未被渲染的全页不能当作当前页面依据。

## 6. 后续完整修复顺序与验收条件

1. 以 MATRIX 中每个原始控件/字段为固定清单，先确认设计、状态与业务映射；禁止通过删字段、换选项、换文案来适应旧实现。
2. 完整实现在线五字段草稿、回填、取消、保存与格式状态；处理秘密字段的遮蔽与既有凭据存储边界；再把数据合同、请求适配和错误状态接通。已有高级管理能力另定入口，不能占用该表单。
3. 补全章节停止、语速精度、试听、后台与常亮开关；修正失败回滚与过期结果。能力不可用时如实给出原因，不提供可点但无效的假控件。
4. 对齐全部状态样式：默认、选中、展开、输入聚焦、保存中、失败、取消、重新进入；随后修正文主题映射、快捷窄屏和微小视觉差异。
5. 检查逐项必须记录源版本、实际挂载组件、状态/事件链、本地验证与设备证据。验证通过按“该字段/该路径/该状态”记录，不能用构建成功代替 Make 一致。
6. 用户要求的主共享动效保持。六个核心 Runtime/会话/滚动/AppearanceGeometry/运动几何/手势文件与本轮初始哈希相同；PlaybackGeometry 的变化仅为 TTS 布局端点与系统/在线高度分支，详见 baseline。弹窗/波形缺失的局部动效另列，不能因此替换整个模型。

本次是审计，不是修复交付。在线五字段、全部列出的缺口、V11键盘/保存完整路径、各状态视觉复核、真机和用户验收均未闭合。
