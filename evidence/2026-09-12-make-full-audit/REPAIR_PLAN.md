# 两份 Make 对应页面完整修复方案

状态：待执行方案。依据朗读 Make V17、界面 Make V9，以及本目录 AUDIT.md / MATRIX.md 的 98 个审计单元。本文仅制定修复方案，未修改应用、Core、设计文件，未构建或安装 VM。

目标：完成快捷朗读、完整朗读、在线 TTS 填写弹窗、音色菜单、界面主题/字体/排版及共享控制栏的内容、交互和状态样式；每项分别留下源码、业务行为和视觉证据。主控制栏继续使用用户指定的一个可逆进度及各元素独立轨道。

## 一、执行约束与明确的产品决定

1. Make 明确定义的字段、选项、顺序、字重、尺寸、配色、展开态和局部反馈全部进入固定清单。实现必须适配设计，不再用旧 API 的取值范围改写设计。
2. Quick / Full 共用同一播放、语速、定时和配置状态；展开、收起、反向拖动不重置业务状态。保留主运动模型、手势连续性和各模块运动轨迹，只调整必要的静态布局端点。
3. Make 未实现的后端行为，由本方案明确补齐：真实朗读、真实试听、持久化、失败状态和资源释放。原型无事件的字体导入、主题切换、排版步进仍保留真实能力。
4. 多服务管理、混音、不可用处理、额外翻页模式等既有能力，保留在“设置”下独立的朗读/阅读高级配置入口，不插入 Make 的五字段弹窗或替换其开关。本入口是生产适配方案，不声称来自 Make；执行前先复用现有设置入口，避免重复页面。
5. 已有书源、书架、阅读进度、配置、服务 ID、请求 header 和自定义规则全部保留。进入页面不强制重置为 Make 演示默认值。
6. 本方案不承诺任意第三方 TTS 接口天然兼容五字段。接口鉴权、请求结构和 PCM 元数据不是 Make 提供的内容，由实现阶段核对现有服务配置并形成明确适配合同；这不影响五字段 UI 必须完整，也不能成为删项理由。

## 三、在线 TTS 的完整实现

### 3.1 路径与状态

- 点击“在线 TTS”进入在线分支，显示“服务信息”；点击“立即配置”才打开填写弹窗，不自动弹出服务管理列表。
- 没有配置时，仅允许浏览/填写，不把不存在的服务当成已生效引擎，也不因浏览页签而停止已有会话。播放区仍管理真实会话，停止操作不能被未配置页签阻断。
- 有配置时，选择在线引擎走可等待的切换事务。完成后才提交实际引擎；切换失败保留原引擎、原选择和可恢复的阅读位置，并显示原因。不要用“配置记录存在”当作网络服务已经验证可用。
- 保存表单与启用服务区分结果：保存失败保持草稿；保存成功但启用失败说明“配置已保存，启用失败”，允许重试启用，不重复新建记录、不伪装旧记录未保存。
- 由会话所有者决定切换期间如何暂停与继续，保持原播放/暂停意图；异步结果必须绑定当前编辑身份、服务 ID 和会话代数，过期结果不能覆盖后来的操作。

### 3.2 五字段一项不减

| 字段 | UI与默认 | 保存/执行要求 |
|---|---|---|
| 服务名称 | 空；例如 Azure 语音；文本框 | 去除首尾空白后用于服务名称与回显 |
| 接口地址 | 空；https://api.example.com/tts；文本框 | 作为真实端点/已有模板来源；校验失败在字段附近提示 |
| API 密钥 | 空；填入访问密钥；遮蔽输入 | 可选；区分保留旧值、修改、明确清空；不把遮蔽占位符保存成密钥 |
| 发音人 / 音色 | 空；例如 xiaoxiao；独立文本框 | 可选；写入所选服务的实际请求映射，不能只改显示标签 |
| 音频格式 | MP3/WAV/PCM三选一，默认MP3 | 选中状态、保存值、请求格式和音频执行一致，不静默退回其他格式 |

名称和地址为生产有效配置的基本条件；不擅自把密钥与音色全部设为必填。按钮/字段错误与保存中的反馈是必要生产补充，正常态严格保持 Make。

### 3.3 草稿与窗口

打开时从已保存配置建立完整草稿。取消、关闭、点遮罩丢弃未提交草稿；重新进入回填上次成功保存值。重启应用也应保留五字段及格式选择。

严格按 Make：最大宽364、左右13、底部16、圆角22；输入高42/r10；中部五项滚动、最大高度440；取消/保存44高，固定在滚动区域外。补齐聚焦1.5 teal边线、关闭命中区和spring进入/退出。

软键盘采用窗口实际可用尺寸布局，聚焦字段可滚动到可见区，底部操作不被遮挡。收起键盘/关闭弹窗后恢复进入前的窗口避让模式，避免影响阅读页及其他弹层。V11只有相关代码，不以它为已通过基线。

### 3.4 数据与请求合同

Core继续负责配置身份、持久化和请求描述；Harmony负责系统凭据、网络和音频执行。

- 先核对现有兼容合同，在Core增加可版本化的配置扩展，保存voice、format及鉴权绑定等信息；Harmony严格编解码同步更新。保留现有HttpTTS字段和导入/导出语义，不直接改写已有自定义模板。
- 密钥使用平台既有凭据机制；Core保存稳定引用或遵循既有明确的凭据边界。编辑时保留未改的密钥；保存失败不能留下不可达的新凭据。验收输出对密钥脱敏。
- 为每种支持的请求方式明确密钥放在哪里、voice/format如何编码、语速如何传入。不能根据“Azure”等服务名称字符串猜协议，也不能把所有API密钥固定拼成同一种Authorization头。
- 保留现有GET模板兼容路径。若目标服务需要POST、特定请求体或鉴权，补对应明确适配器及descriptor，而不是只在UI增加字段。所有五字段要能从编辑一路追踪到实际请求。
- MP3/WAV走明确可解码的音频路径；PCM必须拿到真实采样率、声道和采样格式后处理。元数据来自已定义的服务合同，不能凭扩展名猜测。该路径未经验证就保持未完成，不删掉Make的PCM选项来掩盖能力缺口。

此部分的请求协议细节需要开发前的现有配置核对与合同设计；由实现负责推进，不以再次索要接口文档替代已确认的UI修复。

## 四、补齐朗读全部行为

### 4.1 定时

- 完整页：不开启、15、30、45、60分钟、本章结束；快捷循环：不开启、15、30、60分钟、本章结束。
- 自定义默认25分钟，1–180分钟，±5，边界禁用；完整/快捷显示同一设定。
- 定时模式显式区分关闭、截止时间和章节结束，不再把章节结束编码为90分钟。
- “本章结束”绑定当前朗读章节身份，在最后一段真实播放完成后停止，阻止自动接下一章。重复完成回调不得再次推进；手动换章应清除旧章节的一次性停止目标，避免稍后误停。
- 暂停和进入后台不重新起算绝对定时；继续、切页也不丢失截止时间。应用重启恢复显示时明确区分保存的偏好和已经结束的活动定时。

### 4.2 语速

- 0.5–2.0，步长0.05；预设0.75、1.0、1.25、1.5；支持两位精度的回显。
- 新模型建议使用整数百分比50–200、步长5，避免浮点比较和重复舍入；在平台边界转成真实倍率。
- 保留旧1–10 rate字段的兼容含义，以版本化精确值补充，旧值按已有映射迁移。不能直接把老整数重新解释为百分比。
- UI、会话状态、Core队列、持久化和Host共同核对，重启后0.75不能变0.8。系统和在线两个引擎分别验证实际音频执行。
- 编制方案时再次核实：当前coordinator使用round(rate*5)，当前HTTP Host构造请求仅传id/text，未消费request.rate。因此本项是数据和执行链修复，不只是更换四个按钮。

### 4.3 音色与试听

- 整行52高入口可点；菜单按Make头像、名称、说明、标签配色、独立试听按钮和选中勾绘制。
- 目录使用设备真实可用音色并映射可用元数据；不伪造六个必定存在的示例音色。
- 选择音色改为可等待操作：成功后提交UI与持久化；失败保持原值并提示；快速连续选择只允许最新有效结果生效。
- 试听是独立短会话，不更改正式音色、不提交阅读进度；再次点同项停止，换项终止前一项，关闭菜单立即释放试听。试听期间暂停正文会话，结束后仅在会话身份和用户意图未改变时恢复。
- 在线发音人以在线表单voice字段管理，不再显示“去管理页编辑”但找不到字段的提示。

### 4.4 四个播放配置开关

按Make顺序保留：跟随高亮（true）、来电自动暂停（true）、后台播放（true）、朗读时屏幕常亮（false）。默认只用于没有保存值的新配置。

- 跟随高亮和来电暂停检查现有实际路径；持久化、再次进入与实际执行一致。
- 后台播放绑定媒体/后台租约。关闭时进入后台暂停；打开时按真实平台能力继续，申请失败返回可见结果，不保持“已开启但实际无效”。
- 常亮仅在已启用且正在正式朗读、页面可见时持有自己的租约；暂停、停止、错误、离开或销毁释放。不能覆盖其他页面原有常亮策略。
- 混音、失败跳过等额外能力移至独立高级配置，不能占用这四个位置。

### 4.5 快捷与完整的控制语义

按Make文案接线：快捷上一句/下一句，完整上一章/下一章；到首尾禁用。通过同一会话和章节调度器执行，不另建一套朗读队列。播放/暂停/停止与进度仍保持共用，切换面板形态不触发控制动作。

## 五、主题、字体、排版和完整视觉修复

### 5.1 主题

八个名称/色块继续按Make；把正文、文字、纹理、系统栏及控件需要的颜色收敛到同一主题身份，避免“靛夜色块蓝、正文棕”。

Make未定义八套完整正文配方，因此先做八主题静态对照页：保留既有纹理结构，按Make色块作为配色依据补正文/文字/系统栏的配方，明确标出这些补充；检查文字可读性与快捷/完整主题同步后再绑定真实切换。默认控件强调色按Make保持#2f6373，不另造八套控制栏强调色。

### 5.2 字体与排版

- 八字体、默认第三行导入、拖动排序、设为日/夜主题全部保留真实动作，按Make改可见样式。
- 四下拉按Make内容与顺序：缩进（无/1 字符/2 字符）、简繁（原文/繁转简/简转繁）、翻页（平移/仿真/淡入/无）、对齐（开启/关闭）。
- “无”映射现有none；在现有翻页调度内补淡入呈现，不重写仿真/平移算法和输入所有权。覆盖/滚动保留为高级模式，不插入Make这四项；读取旧偏好时不静默改成其他模式。
- 字号、行距、段距、字距步进器不仅回显数字，还需实际重排并保存。格式18px/1.96/16px/0px只作为示例，不覆盖已有偏好。

### 5.3 所有状态的样式与局部反馈

依MATRIX逐项修正默认、选中、展开、播放、暂停、空闲、聚焦、保存中、错误、取消、重入状态：字重/字号/行高、圆角、边线、填充、间距、图标尺寸和阴影。

播放波形跟随真实playing状态启动；暂停/空闲为4高灰条。快捷状态点、左线和文字同步变灰。波形、开关、菜单、弹窗有各自局部反馈，但不得驱动或替换主控制栏共享进度；不可见时停掉装饰动画。

快捷窄屏优先重新分配标签与按钮空间，保证“朗读中/已暂停/未开始”等主要状态完整；长错误提供可达的详细反馈，不用无限缩字或固定裁剪蒙混通过。

首次导航点击问题先记录事件时间、实际命中、输入门禁原因、窗口尺寸更新及会话身份，定位后改具体根因；不加固定延时、自动补点或要求用户再点一次。

## 六、验收与交付

### 6.1 本地与合同验证

对真实缺陷建立有意义的回归：五字段保存/回填/取消/空值、旧配置保留、失败重试与重复点击；精确语速往返；章节边界停止；音色失败与过期回调；试听不改阅读进度；后台/常亮租约释放。测试输入来自Make清单和实际失败场景，不仅检查“源码存在一个按钮”。

### 6.2 视觉与交互验证

- 同一逻辑视口对比Make与应用，至少包含参考390宽及此前截断的窄视口。
- 快捷/完整、系统/在线、无配置/已配置、弹窗五字段和键盘、六类音色样式适配、四下拉、八主题及字体/排版状态逐项留证。
- 主动效检查端点与中间帧、反向拖动、松手再抓、收起途中恢复；播放/定时/选中值不跳变。
- 冷进入首击、关闭弹层后首击、窗口尺寸稳定前后的输入、取消重入、保存失败重试均进入路径清单。
- 系统朗读与在线实际发声、三种音频格式、试听、定时到点/章节结束各留单独行为结果。第三方真实端点未验证时明确剩余范围，不用本地假服务冒充真实兼容。

### 6.3 产物和设备边界

内容与本地回归齐备后走项目唯一HAP流水线，生成绑定源码的manifest；重新确认现有VM身份、就绪和占用后保数据部署。代码、构建签名、安装启动、交互、视觉分列状态。需要真机的剩余问题遵守工作区“先代码定位、明确最小取证目的”的要求，既有VM授权不外推成任意真机授权。

交付清单逐项标记：已修且已验证、已修待验证、未修/受限；提供同一个候选包的证据。98项逐一闭合前，不再给出“全部严格遵循Make”的完成判断。
