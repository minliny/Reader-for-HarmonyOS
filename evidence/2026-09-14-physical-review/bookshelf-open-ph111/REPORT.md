# PH111 书架点击后的响应延迟

用户反馈点击书架书籍后需要等待片刻才有反应。尚无本次书籍身份、具体秒数或设备 trace。当前源码 Harmony `5fb96de4` + PH104–110 工作树，Core `bf4949531`；最近真机安装 run `20260916T045509Z-5fb96de4-a001d8e7`，signed SHA-256 `e1dd1b87673f45b97f2f336d54c9f348b9313dd87567dbac9c451c59cb652b71`。

先记录并审计 BookshelfPage 点击/长按、Index.openShelfBook、本地/远程目录正文准备、首次排版、路由呈现和反馈状态；保留书架直接阅读、首屏提交后切路由的既定语义。当前仅做代码审计和本地生产方法探针，不操作设备。

源码原因、本地回归、产物、真机响应时间和用户验收分别补记；真实设备等待时长尚未测量。

## 已确认的代码原因与修复

1. 点击后 `shelfReadingPreparation=true`，书架整页被禁用，但原界面完全没有消费该状态来显示反馈。用户需要等目录、正文、排版和首个进度提交全部完成才看到路由变化。现立即显示选中书名与“正在打开…”以及取消入口；取消复用既有导航代次和阅读退出流程。反馈在首屏提交、取消或失败时移除，应用日夜色及减少动效/后台状态均有响应。保留书架直达阅读，不闪详情页。
2. 本地目录加载后，原代码立即发 `cache.book.status`、`bookmark.list`，随后才请求挂载阅读器。它们会先于首次正文准备进入 Core 通道，却不是首屏条件。现将附加投影延至首个已提交页面后执行，并隔离取消、同书重开和晚到结果，保护较新书签。修前调用顺序和本地回归见 附加投影审计（原始证据仅本地保留）。
3. 首次正文 I/O 还被 `layoutReady` 串行挡住；正文读取不依赖字体/窗口排版参数。现让正文与布局同时准备，章节发布和测量仍须等全部准备完成。实际旧源码探针显示布局未完成时正文请求 0 次；修后正文请求 1 次，但章节发布/测量仍为 0，释放布局后只测量一次。退出、新选章、缓存刷新递归及提前拒绝均已回归，见 首屏并行审计（原始证据仅本地保留）。

联动审查发现：防重复点击若放在公用 `openShelfBook` 内，会误挡换源失败后的恢复原书。最终只在真实书架 `onBookSelected` 回调处拦重复点击，内部恢复不受影响。另确认既有 Back 在换源目标首屏未提交时会遗留 pending 事务；本次对当前书籍匹配的持久换源窗口沿用 `closeSourceSwitch` 的不可取消规则，反馈显示“正在切换书源…”，取消暂不可用且 Back 不撤销导航。判定复用 `currentSourceSwitchTransactionId`，其他书籍不受残留 pending 影响。普通阅读准备仍随时可取消。

未发现源码显式设置单击等待 500 ms；500 ms 是独立长按阈值，不能视为本次等待实测。TOC 复用、内置字体进程级注册、非首屏聚合指标已有优化，不重复引入缓存/解析器。上述改动复用 ArkUI 原生 LoadingProgress、现有 Gateway、取消和持久化能力，仅调整 Reader 业务反馈与时序。
