# 朗读完整控制页交互修复

用户报告：VM 中朗读完整页的 TTS 配置无法交互，要求同时检查并修复相关缺陷。

现场版本：Harmony HEAD `35f2f99a8d635615475fde75120bf8629f944565`，当前 dirty 工作树；上一部署 run `20260911T133517Z-35f2f99a-92f2b4a4`，签名 HAP `a3adb1d2544a49ee53ffd2f44a809a5e6d2fee9efc0a60f47dffcbfc277be0bb`。

代码审计已确认：

1. `ReaderControlTtsContent.ttsSelectValueField` 对引擎、语言、音频会话、不可用处理仅展示文本，写明“暂不可展开”，没有选择入口。已有产品表面检查甚至要求保持无点击事件；本次用户明确要求补全交互，应同步更新该旧约束。
2. `ReaderHttpTtsManagerPanel` 已具备 Core 配置增改删回调，但生产页面未挂载；在线 TTS 无配置时直接 return，点击没有反馈。
3. 音色仅通过 `selectNextVoice` 循环，不能直接查看并选择候选项；在线模式仍展示系统音色，含义容易误解。
4. 配置表单提交期间仍可编辑、清空或切换编辑对象，旧保存回调会清掉新草稿；异步回调缺少卸载后的失效保护。
5. `ReaderTtsSessionCoordinator.setRate` 在判断当前值相同之前使朗读 token 失效，重复选择会丢弃后续音频回调；暂停状态也无条件调用 `speakSlice`。Core 当前 `tts.set-rate` 保留暂停状态，问题位于 Host 协调层。
6. 语速与句子进度滑块仅接收 End，未处理 SDK 的 Click 值变更；补齐点击并防止一次手势的 Click/End 重复提交。
7. 混音设置仅写入会话 input；两个平台音频适配器已激活后直接返回，播放中的会话策略没有更新。改为同策略不重复激活，策略变化重新应用；平台多应用音频竞争效果仍需单独验证。
8. Host 在 TTS 服务未初始化时对配置增改删直接返回，界面会将其当作成功。改为明确失败反馈，保留草稿。

继续检查：音频会话实际应用时机、配置失败回写、播放与滑块点击回调、临时层关闭及形变输入屏蔽。代码能定位的问题先修复并做本地回归。VM 仅做修复后最小交互验证；不占用真机，不把编译或安装当作交互验收。
