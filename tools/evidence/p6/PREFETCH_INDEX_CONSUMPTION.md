# Reading optional prefetch: original owner consumed by Index

The production Index no longer stores a rolling-window queue/task/latest key, readable TOC position index, or catalog refresh/attempt/in-flight maps. The original `ReadingPrefetchHost.forRuntime` owns all of those facts. Index supplies a finite captured presentation lease, current directory/session DTOs and existing publication/diagnostic/navigation seams. Explicit shelf prefetch keeps its separate per-book mode; reader work retains the existing canonical five-readable-chapter window. Persisted lastCheckAt seeds the same owner, not a second time map.

`test-reading-rolling-prefetch` now executes complete actual Host/Gateways behind unchanged Index delegates. Its 16 original producer/resource/mutation/budget scenarios remain; the two added scenarios cover same-Runtime physical Index reconstruction without forking the accepted native producer, and registered SDK Index attributes → actual retained ReaderShell ForEach → ReadingExperience child prove live directory metadata Props and the same reader identity after a row patch. Only generated SDK observers replay after first mount, so the test does not invent whole reader remounts. A retired physical reading commit dispatches no optional IO.

`test-reading-catalog-refresh` retains the 1370 chapter/949–950 boundary, original page/progress/measurement ownership, exact catalog compatibility, late callback and retry cases. Its private-state inspection points at the actual feature owner. The obsolete old test permitted a second native refresh when the first presentation retired; the actual owner deliberately holds that native lane until real settlement. The new test proves no second flight before settlement, no old result publication, and an explicit current retry afterward.

`test-reader-directory-business-boundaries` retains sparse readable indexes, constant-time repeated progress, cancellation and real manual shelf update boundaries. The cached position index is inspected in the original Host; no production duplicate is retained to satisfy the old test location.

Validation is actual source/SDK parse and observer execution with controlled Core/native IO, not native frame/focus timing, a full HAP or device acceptance. ReadingEntry/Directory/Offline actual Index consumption remain independent pending families. During broader fixture audit, the older direct-entry and search-trial tests still extract removed SourceSwitch Index owner classes/methods; those real journey assertions must migrate to actual SourceSwitch/Entry owners rather than reintroducing duplicate production code.
