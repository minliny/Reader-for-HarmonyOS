# Asset physical inventory target question

This is a cold debug opt-in `readerAssetInventoryProbe=true`, emitted as `READER_ASSET_INVENTORY` after the existing recovery barrier. Normal startup and warm Wants do not scan. Official installed SDK `@ohos.security.asset.d.ts` specifies `query`, `ReturnType.ATTRIBUTES`, `RETURN_LIMIT` and `RETURN_OFFSET`. The bounded probe makes at most 64 pages per pass (64 rows/page), twice; it does not manufacture a platform prefix filter.

The target question is whether this OS supports paginated application metadata enumeration and whether Reader WebDAV physical alias counts change across cold starts and settled configuration operations. Reports include counts of the legacy alias, UUID-shaped immutable aliases and other Reader-prefix aliases, plus **alias metadata bytes**. Secret/storage bytes are explicitly unknown. Individual aliases, credentials, user strings and exception messages are never logged. No `SECRET` access, create/update/remove, configuration head/intent read, authority qualification or unlock is performed.

Two unchanged bounded scans are an **observation**, not an atomic inventory snapshot. Duplicates, malformed metadata, caps, differing identities or platform errors remain unverified; retirement suppresses late results. A platform `not found` error is not reinterpreted as a confirmed empty inventory. Pagination may be unstable during mutations, and an IPC need not settle within the page bound. Target runs require settled operations, before/after source/artifact/device binding and a host time limit; do not turn a timed-out scan into absence.

An alias is not classified as an orphan by name/absence of a current reference. This probe cannot authorize cleanup, release an unknown original mutation or assert at most three physical records. Head, original pending and previous cleanup qualifications belong to the actual credential owner. Repeated observations and native settlement evidence are needed before changing recovery/collection policy. Existing user data and Asset records remain untouched.

Local test exercises the entire production probe against a controlled native API seam, including real paging, identity changes at equal counts, caps, malformed/duplicate results, platform failure and old owner retirement. It is not OS enumeration, crash durability, resource-budget or HAP acceptance. Final canonical ArkTS/HAP and exact target measurements are required separately.
