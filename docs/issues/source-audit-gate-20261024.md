# 书源常规检查 sealed 流程（v2，probe-then-chain/v1）

常规检查固定通过 `Reader-Core/tools/reader-cli/source-audit-gate.mjs run` 进入。入口不提供跳过网络、强制执行、无批准或直接绕过参数。

执行前必须同时满足：

1. 合并规则文件、直连/代理网络预检结果和通用关键词文件的 SHA-256 已冻结。
2. 网络预检覆盖每个规则 origin 的直连和 `http://127.0.0.1:7890` 代理结果；未通过的规则不进入 `source.check.run`。
3. 存在人工批准文件，并绑定上述三个 SHA、两个 lane 和本次常规书源检查范围。
4. 使用完整 `reader-cli --source-check-run`，不使用目标小说搜索或 80 章任务替代常规检查。

每个规则版本先解析能力入口：

- 有有效 `searchUrl + ruleSearch`，生成 `mode=search` 路由；
- 有 `exploreUrl`，生成 `mode=explore` 路由；
- 两者都有时生成两条独立路由；
- 两者都没有时记为 `NO_BOOK_ENTRY`，不伪造搜索任务。

搜索路由使用源自己的 `ruleSearch.checkKeyWord`，然后追加人工确认的通用关键词文件中的 `什么、我、之、的、不`。Core 解析源规则时会以源自己的关键词覆盖命令级 fallback；为执行通用探测，fixture 会显式绑定本次探测词，并在结果中记录 `keywordOverride`。无 `checkKeyWord` 的规则保留 `MISSING_SOURCE_KEYWORD` 事实，不用默认值掩盖规则缺失。

发现路由不使用关键词。它从 `exploreUrl` 找到可用推荐分类，返回推荐书后直接沿推荐项的 `bookUrl` 执行详情、目录和正文链路；空 `ruleExplore` 遵循 Core 的搜索规则回退语义。

文本路由请求 L1–L5；非文本媒体路由请求适用的 L1–L4，并将媒体 L5 留给对应媒体能力检查，不把文本长度门槛误判为媒体通过。每个路由的结果按规则指纹、lane、路由、关键词和请求级别保存。

搜索关键词分成两个阶段，不能把每个关键词都重复跑完整链路：

1. `probe` 阶段只请求 `L1,L2`，判断规则是否能返回可解析的书籍候选；源自己的 `ruleSearch.checkKeyWord` 优先执行，只有缺失、无结果或后续链路失败时才进入通用关键词。
2. `chain` 阶段只对第一个通过 `L2` 的候选请求适用的完整链路。文本路由执行 `L1-L5`，非文本路由执行 `L1-L4`；链路失败后结束当前路由，不为同一路由再次把剩余关键词全部跑一遍。

发现路由同样先执行一次 `L1,L2` 探测，再执行一次完整链路。每个路由最多一次探测序列和一次深链，避免把搜索探测和正文验证混为同一个昂贵操作。

源自己的关键词沿用 180 秒 Core 预算，通用补充关键词使用 30 秒预算。CLI 外层只保留 5 秒进程退出宽限，避免把 30 秒请求扩大为近 50 秒。单个关键词无结果只记 `KEYWORD_NO_RESULT`，不单独判源失效；所有候选关键词都失败才判路由失败。搜索和发现的可用性分别汇总，不把目标书是否命中混入常规状态。

结果按规则版本、sourceId、lane、路由、阶段和关键词断点复用；旧 v1 runner 结果不复用，旧 v2 全链路 attempt 也不会被新的阶段 fixture 误复用。每个 attempt 明确记录 `phase=probe|chain`，路由记录 `stopReason` 和阶段摘要，历史 attempt 不参与新一轮路由统计。输出目录必须有匹配的 `plan.json` 锁；没有锁的旧结果目录拒绝继续写入，避免不同策略混合计数。中断后只重跑未完成 lane，已完成 lane 直接复用。并发、超时和 `executionPolicy=probe-then-chain/v1` 写入本次计划，人工批准必须绑定这些执行语义，不能由外部参数绕过入口。
