# 两轮应用性能审计修复记录（2026-09-23）

## 范围与版本

本记录对应近期两轮代码侧审计确认的六项应用使用路径问题，并记录修复复审中新发现的一项暂存文件权限问题。修复起点：Core `446ba601d856d3ffda8fe8259b2779730f8a9e8f`，HarmonyOS `81f561d30356884be40366fb8957ba3564dcbdf5`。两仓独立管理；以下结论只覆盖本轮列出的路径，不覆盖历史总账里的其他开放项。

## 问题、定位和修复

| 编号 | 现象与触发 | 代码侧证据和结论 | 修复与回归 | 未决边界 |
| --- | --- | --- | --- | --- |
| P01 | EPUB 有较多链接 CSS 时，可选样式读取消耗与 OPF、目录及正文共用的 256 MiB 解压预算；后续必需正文可能被拒绝。 | Core `reader-local-book/src/epub.rs` 中所有 ZIP 文本原先共用同一预算。宽度样式是可选信息，正文读取是准入条件。 | 给 CSS 独立的 32 MiB 总预算，保留单条目 32 MiB 上限和正文 256 MiB 预算；用两章节真实 ZIP 解析测试验证 CSS 不挤占第二章预算。 | 尚未用目标设备测大 EPUB 导入耗时。CSS 超过独立预算时省略可选宽度提示。 |
| P02 | 图片数与 CSS 规则数同时增大时，图片宽度计算可进行大量选择器匹配。 | Core `epub/image_style.rs` 的宽度级联逐图遍历规则；`epub/image_geometry.rs` 已扫描图片，可复用该计数。 | 在每篇 XHTML 投影前预算最多 10 万次图片×选择器匹配；超出时整篇省略可选 CSS 宽度提示，正文、锚点及图片几何仍保留。定向测试覆盖超限退化与正常宽度。 | 复杂单次 CSS 解析或 DOM 投影仍是有界步骤，设备 CPU 峰值未测。 |
| P03 | WebDAV 响应资源每 1 MiB 写入都等待磁盘 `sync_data()`，同步 Host 调用会累计等待。 | Core `reader-runtime/src/asset.rs` 的暂存响应资源在同一进程读完并释放，提交检查完整长度；没有重启后持久恢复合同。 | 移除逐块强制落盘；保留写入、长度核验、读取与释放。多块提交及取消后删除测试验证数据完整性。 | 未测设备文件系统下的 p95/p99 延迟。 |
| P04 | 冷启动书架首屏等待全部内置字体和当前阅读字体；自定义/正文专用字体把书架显示绑在无关工作上。 | `EntryAbility.ets` 原先把完整字体准备接入 `startup.theme` → `recoveryReady` → `loadMainContent`。 | 首屏只等待书架实际使用的 Inter、Noto Serif SC Bold、Noto Sans SC 的原生检查回执；阅读专用字体在恢复后后台准备，阅读布局仍由自身检查回执准入。聚焦启动与字体测试覆盖慢字体、设置恢复和首屏门禁。 | 首像素、阅读首字形及自定义字体切换的设备时间未测。 |
| P05 | 老版本本地 EPUB 图片样式修复在后台整文件读取、哈希、解析与逐章投影，前台阅读意图到来后不能及时停止。 | Core `remote/local_image_presentation.rs` 原来只在解析前后及章节间检查请求预算。 | 分配前检查，文件读取/哈希按 1 MiB 检查，EPUB 解析在每个样式元素、图片及文档间检查，逐章派生和原子发布前检查；超时/取消保留原 Core 错误，取消时不发布 marker 或章节改动。真实 EPUB 回归验证取消后重试。 | 一次有界 ZIP 读取、CSS 解析或 DOM 投影完成后才可响应取消；无设备耗时数据。 |
| P06 | 书架首次显示后，自动目录检查和持久阅读准备可分别扫描整架，书多时重复分页和 Core 调用。 | `Index.ets` 的两个后台入口各自调用 `BookshelfFlowGateway.loadAll`。 | 在同一 Runtime owner 和书架 projection revision 下共享自动检查得到的完整身份列表；失败、禁用自动检查或版本变化时走原 membership 扫描，旧版结果不进入预备。Node 生产方法探针覆盖完整书架、离屏项、回退及版本围栏。 | 尚无设备书架量级的分页次数与首屏时序测量。 |
| P07 | 复审发现：WebDAV 暂存响应在共享临时目录下可能继承 `0644` 权限，其他本机用户可读；可预测文件名还可能被预占导致写入失败。 | Core `AssetStore::begin` 使用 `create_new` 防符号链接抢占，但没有明确私有 mode，文件名只含进程和计数器；路径可落在共享系统临时目录。 | Unix 创建时明确 `0600`，文件名加入现有 `getrandom` 提供的 128 位随机后缀；加入实际文件权限回归，保留 owner/generation、完整长度和释放删除检查。 | 设备文件系统的权限行为仍需随目标包验证；本地测试只证明当前 Unix 环境。 |

## 数据、开源能力与证据边界

本轮复用现有 ZIP、HTML、CSS 选择器、SHA-256、SQLite 与书架网关能力，只调整预算、调度和取消边界；没有新增通用解析器或缓存算法。没有清理书架、下载正文、阅读进度、书签、批注和高亮，也没有运行 VM 或真机操作。

代码侧定位和本地回归可证明上述路径的预算、取消、版本隔离与数据不变式。签名 HAP 的构建/校验、VM 行为、物理首像素与用户验收分别记录；本文件不把本地测试当作设备性能达标。
