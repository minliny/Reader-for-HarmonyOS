## 4. 建议的统一实现结构

### 4.1 控制会话：唯一的状态裁决者

建议新增 `features/reading/ReaderControlSessionState.ts`，以纯状态转换处理事件，由 `LocalReadingExperience` 持有这一份会话。

至少表达：

- 控制生命周期：隐藏、打开中、已显示、关闭中。不可见但手指仍持有时仍属关闭中，不能提前变为隐藏。
- 内容层级：初始／二级，以及当前模块。
- 目录模块标签：目录／书签；不引入第三层业务页面。
- 当前稳定形态、目标形态及前进来源。
- 当前操作的逻辑目标，供连续系统返回后退；不能只看上一次到达的稳定端点。
- 当前转换类型：整栏打开、快捷／完整互变、整栏关闭；关闭前会话与当前画面快照。
- 有效手指、最近明确方向、暂停前目标、操作代次、关闭提交代次。

统一接收 `OpenControl`、`EnterModule`、`Expand`、`Collapse`、`Dismiss`、`Back`、触摸、帧推进、尺寸变化、取消与业务完成事件。

强约束：

1. 初始页不能产生 Full 状态。
2. Full 不改变模块、标签与业务服务身份。
3. “按下”“路由改名”“达到某个 p”均不能单独清空会话。
4. Back 决定操作目标，不依赖画面过半。
5. 只有有效关闭终点且无手势持有才能提交隐藏与初始页复位。
6. 旧动画／旧输入事件通过代次校验失效；不得延迟覆盖新操作。

### 4.2 输入与帧驱动：所有模块共用

建议新增 `ReaderControlGestureDriver.ts`，由 ArkUI 适配层转入同一套生产事件处理。

- DOWN 记录当前帧与原目标，暂停自动驱动；不触发点击、不改当前进度。
- MOVE 使用实际屏幕坐标的增量推动整栏，小横条位置不能再被第二次 ease-out。
- UP 区分点击、发生明确移动的拖动／甩动、长按未动；沿已确认方向／原目标继续。
- 最近明确方向与瞬时速度分开保存；停住后速度归零，不等于丢失最近方向。
- 不用半程／预测位置决定终点；点击防抖识别不得变成完成轨迹门槛。
- 触摸段结束只结算一次，不能同一 UP 又触发背景点击或按钮点击。
- 新一次明确背景点击／Back 可接管动画，不能以“动画 busy”为由一律拒绝。
- 使用现有帧回调机制作为候选接入点，正式开发时核对本地 SDK 的输入／帧 API；本轮不宣称 API 方案已通过运行验证。

现有外观状态中的代次保护、实测坐标、按实际时间推进和重新抓取不跳帧可提取复用，但须逐条通过新契约，不能整份改名视为完成。

### 4.3 动效采样：同一时刻只有一个活动过程

建议新增 `ReaderControlMotionGeometry.ts` 与 `ReaderControlMotionStage.ets`。

- 快捷／完整互变由一个进度生成主体、上层内容、亮度、导航和完整专属内容的全部属性。
- 整栏关闭从当前画面捕获起始状态，所有组件沿同一个关闭进度到隐藏；不先把展开进度拉回 Quick，避免快捷专属内容复活。
- 关闭中反向沿当前关闭路径连续返回；完成关闭前保留原会话。
- 打开／关闭与快捷／完整是不同转换，但不是分别竞争更新界面的独立动画时钟。
- 任一时刻只由一个活动转换和驱动写视觉帧；组件只消费结果，不私自播放独立的 delayed animation。
- 窗口变化重新计算几何并保持当前屏幕位置／触点锚定；不能继续用固定 364 宽或固定设计行程作为实际触摸距离。

数据映射建议新增 `ReaderControlMotionSpec.ts`，记录模块、语义组件 ID、Figma 节点、原始属性、用户调整规则 ID、目标轨迹、裁切与层级。

来源保存为三层：恢复 Figma 原始记录、本文引用的明确调整、编译后的目标轨迹。原始记录不为了跑绿而改写；目标期望也不从生产采样函数反向生成。

### 4.4 组件结构：共享身份，不复制整页

统一动效容器持有主体、顶部／小横条、亮度、导航与模块内容；各模块提供内容和自身组件映射，不控制全局开关与返回。

- 共享语义组件在快捷与完整之间保留身份，通过布局、裁切、位置和大小连续变化。
- 完整专属组件可以独立存在并随统一进度显露；“独立组件”不等于必须把整套 Quick 与整套 Full 都复制一遍。
- 列表、输入、选中状态不得因切形态而重新初始化；避免双列表、双输入焦点、双事件入口。
- 隐藏或不属于当前输入面的组件不能截获点击、朗读焦点或列表滚动。
- 保留目录／书签虚拟化、稳定 key 与已知复用安全措施，只有验证后才能撤销既有防护。

### 4.5 列表与业务接线

建议新增 `ReaderControlListPositioning.ts`，将目录和书签定位变为可执行的纯策略。

- 每次新打开分配 `listOpenRevision`，记录目标锚点、数据就绪与用户是否已经滚动。
- 快捷／完整互变和关闭撤销不增加打开代次。
- 目录以当前章节作为目标，按实际窗口尺寸居中并限制在真实边界内。
- 书签首先比较章节序号距离，再按阅读顺序靠前处理等距；不拿创建时间代替阅读位置。
- 数据稍后到达时最多提交本次有效定位；用户已经滚动或新打开代次产生后，旧定位无效。
- 视口改变保留列表内容锚点，不触发可见的回顶或重复居中。

选择事务继续使用真实书籍身份、章节索引和章内偏移，增加明确的“请求—准备—阅读锚点提交／就绪—成功关闭／失败保留”链。

选择请求代次与控制栏关闭代次分开：撤销关闭不回滚成功选择；旧选择结果也不能把已关闭或已切换到另一会话的控制栏重新打开。

保留 Core、读取／保存、书签 CRUD、TTS、自动翻页和设置网关。只有发现现有宿主接口无法表达明确需求时才做窄适配，不扩大为 Core 重写。

## 5. 开发顺序与每阶段退出条件

### 阶段 0：固定输入与保护现状

1. 记录执行参考版本和开工时 Git／未提交差异边界。
2. 提取所有模块正确设计节点、端点、中间轨迹、组件身份与裁切／层级；包含目录／书签与所有展开收回组。
3. 把本轮亮度、同步变形等调整单独列为显式目标覆盖，不冒充旧稿原值。
4. 建立全模块迁移清单和新验收用例；识别旧测试冲突。

退出条件：每个模块均有来源和目标映射；缺失数值明确待取，不用旧常量或通用淡化补齐。

### 阶段 1：先完成可执行的控制会话与手势规则

开发统一纯状态与驱动，先在可控事件／时钟下验证，再接入真实组件。

退出条件：初始无展开、层级返回、动画中连续返回、长按暂停／续播、明确方向释放、关闭终点持指不提交、旧回调无效等用例均可执行验证。

### 阶段 2：统一容器，完成两类代表模块

- 目录／书签：验证同一宿主、同一列表、标签保持、一次定位、成功选择再关、完整态直接关闭。
- 外观：验证亮度、顶部、主题／字体等多个组件在同一进度上连续变形，取消现有专用提前完成／交叉淡化路径。

两者共用同一会话与驱动，不建立两个试验性生产分支。可先在开发验证入口做定点进度检查；未获运行授权时不得标记视觉通过。

退出条件：路由连续性和复杂组件几何均通过各自证据层，才批量接其他模块，避免把错误底座复制到全量页面。

### 阶段 3：迁移剩余模块及特殊入口

按搜索、替换规则、朗读、设置、自动翻页推进，逐项迁移并验证：

| 内容 | 特别注意 |
| --- | --- |
| 搜索 | 输入和结果上下文、异步失败、精确结果锚点、成功后关闭 |
| 替换规则 | 阅读内完整形态与外部规则管理共用内容／服务，不能退出阅读冒充展开 |
| 朗读 | 保留会话、播放／暂停及设置，不因变形重启服务 |
| 设置 | 保留即时生效值、临时层和相关输入归属 |
| 自动翻页 | 移除独立布尔／延时动效调度，保留计时、状态和与朗读的业务互斥 |

迁移总表必须包含目录、书签、外观及以上五项，不能只完成外观就标记全量完成。

### 阶段 4：清理旧控制层与旧测试

只有新链路替代所有相关调用且验证完成后，才移除确定不再使用的控制层：

- 旧上拉阈值与小幅 handle snap 作为展开机制的路径。
- 各模块独立的展开／收回定时器、布尔切页和整页交叉淡化。
- 阅读内目录／替换借用外部页面冒充完整态的路由接线。
- 只按固定动画时长清页的关闭完成机制。
- 与用户规则相反的测试断言和失去生产引用的专用控制代码。

不删除详情页目录、外部规则管理、Core、用户数据、业务网关或仍被使用的组件。旧实现不值得保留不等于本轮获准全量删除仓库；清理按精确调用范围、可恢复差异执行。
