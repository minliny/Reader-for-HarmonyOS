# HarmonyOS source and integration checks

HarmonyOS CI runs the affected pure TypeScript Host domains on branch pushes and pull requests. `scripts/ci/run-impact-checks.mjs` compares the event base against the checked-out commit and invokes `node scripts/test-host.mjs --changed-from "$BASE_SHA" --committed`. The check reports selected and executed domain counts. Documentation and `.reader-artifacts/` changes alone produce `NOT_RUN`. CI rejects newly added ArkUI simulation and source layout regexes in Node files under `scripts/`, `tests/` and `tools/`.

Fork PRs exercise Host wire projections with the checked-in Core fixture snapshot. Trusted runs also compare that snapshot byte-for-byte with the Core-owned fixture from the revision locked in `scripts/core-dependency.json`. Draft PRs run `host-fast-checks` only, skip `core-fixture-parity` and `unsigned-hap-build`, and report `harmonyos-ci-result`; marking a PR ready for review (`ready_for_review`) triggers the trusted verification and publishes the required `harmonyos-ci-gate` check on PRs targeting `main`.

Trusted `main` pushes, non-draft same-repository PRs with code changes and the default manual or weekly trigger build and verify an unsigned arm64 HAP with the pinned `api26r` SDK and the same locked Core revision. Non-scheduled `api26r` runs reuse an exact-key cached Core Native package keyed by `(sdk, image digest, coreCommit, coreInputFingerprint, rustToolchain, abi)` with fail-closed hash and identity verification (`scripts/ci/verify-cached-native.mjs`) on restore; weekly `schedule` builds and manual `api23` and `api24` runs perform cold Core Native builds (and `api23`/`api24` compile Core Native only). The public artifact contains the manifest, source snapshot and build summary with five-day retention. Native outputs stay in the build job's temporary workspace or exact-key cache. Signed builds and VM acceptance have separate receipts.

The manual `contracts.yml` workflow takes a Host domain or the complete Host suite and an independent source-hygiene option. Locally, use `node scripts/test-host.mjs --domain <name>` for targeted work or `node scripts/test-host.mjs --changed-from <baseRef>` to include relevant working-tree changes. The workspace verification index covers Core contracts and remote VM journeys. [Verification index](../../GATE_INDEX.md)

Native synchronization uses `node scripts/hap-pipeline.mjs sync-native`. The previous `sync-core` spelling delegates to the same provenance checker and transactional replacement. Inputs must come from a fresh matching Core build, with `core-input-snapshot.json` and SDK smoke evidence. Older generated SO/SDK packages are retained for recovery and are not accepted as inputs for new source.
