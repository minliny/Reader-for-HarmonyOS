# Reading entry/prefetch owners: source and integration boundaries

Clean baseline `11b95d3e`; independent `codex/p2-reading-entry-owner-20261003`. No Index, LocalBookDetail, retained reading component tree, RuntimeOwner, Directory/Offline gateways, typography, Native/SDK/HAP or target writes in this lane.

## Prefetch first slice

The actual Index rolling reader-window producer and near-end catalog producer now have `ReadingPrefetchHost` as one domain owner: pending/active/completed work, single drain, latest requested window, content/Runtime/lifecycle admission, readable TOC positions, unchanged two-before/two-after window, completion backoff, refresh cooldown/attempt/inflight and actual append eligibility. Existing `ReadingOfflineGateway` owns materialization and terminal report cleanup; `RemoteReadingFlowGateway`/BookAcquisitionCoordinator owns canonical acquisition. No replacement parser, matcher, queue service, native protocol or cache policy is introduced.

`forRuntime(capturedRuntime)` returns the same owner across Index remounts and refuses a retired Runtime before replacing the cache. `retire()` invalidates optional admissions and pending UI delivery; active actual Gateway work still drains its native leases/reports. New reader admissions share the old drain, avoiding a second concurrent producer. Refresh timestamps are removed only after their original eligibility deadline has actually elapsed and the corresponding native refresh has settled. A future timestamp/backwards clock is retained. Retirement never expires or replaces an unsettled refresh, even when its old presentation predicate is false. P9 retention/performance budgets remain separate; there is no new entry-count cap, LRU policy or timer.

P5 API: `prefetch(session, preferredChapterIndex, lease, mode)` where mode is `reader`, `shelf`, `opportunistic`. Reader owns one latest window; shelf jobs stay independent and incomplete results throw the existing message; opportunistic work preserves its previous non-throwing partial-result semantics. Lease contains only captured UI `isCurrent`, `displayedSession`, current `directory`, pure `projected(entries)`, `refreshed(session)` and `diagnostic(stage,message)` delivery. The Host captures actual Runtime/content/lifecycle, selects and executes work, patches only changed download states while retaining bookmark/level/navigability fields, and protects state from observer/diagnostic exceptions. Page callbacks must capture navigation/session identity; they must not fetch fresh identity in old callbacks.

`noteCatalogRefresh(identity,lastCheckAt)` consumes the original seconds timestamp; `nearEnd(session,index)` preserves the three-chapter threshold, and `refreshNearEnd(session,lease)` performs actual forced acquisition and existing `canAppendRemoteReadingCatalog`. Changed prior chapter requests require reopen; they never remount or replace the retained reader. The accepted refresh timestamp is independent of UI callback exceptions. Original ten-minute success and thirty-second failed-attempt intervals remain.

P5 removes `ReadingWindowPrefetchIntent`, reader queue/task/latestKey fields, catalog timestamp/attempt/inflight maps and readable-Toc index fields from Index. Existing wrappers may only capture UI admission/DTO projection and call this owner; they may not keep a second window-selection/drain or near-end eligibility algorithm. `installRemoteReadingSession` may drop its old readable-order bookkeeping; Host derives it from the actual admitted TOC array. Reader commit/directory/BookshelfHost real callers must be connected before family closure.

`node tools/test-reading-prefetch-host.mjs` executes the full actual owner plus full Offline/Remote gateways through controlled Core/native IO: 1370 chapters/eight page admissions become one five-chapter window; latest window coalescing; real materialization lease draining on retirement; content revision and immutable row updates retaining bookmarks; thirty-second retry; independent per-book work; unknown indexes; real acquisition/inflight dedup and append eligibility; persisted last-check/cooldown; observer/diagnostic isolation; late catalog retirement; expired-settled deadline pruning with future-clock and native-inflight retention. A mutated actual lifecycle admission reproduces late delivery. This is not Index SDK, native timing, platform memory, target or visual proof; P5 owns actual Index integration and old implementation deletion.

## Remaining ReadingEntry slice

The first Prefetch slice does not close ReadingEntry. Current Index still contains local detail TOC admission, remote cached/group/supplied acquisition, source-name/shelf reconciliation, reading-body verdict/probe, stale-cache recovery intent, background refresh, persisted shelf/viewport admission. These must move as actual finite state/operation producers, not callback IO wrappers. Reuse the actual BookAcquisitionCoordinator, ReadingEntryPreparation, Directory/Offline owners and canonical position validators. Keep page navigation/reader route selection and physical reader tree in Index. Full consumer integration, actual stale-owner/route/book/readiness tuple, recovery callbacks and deletion remain required.
