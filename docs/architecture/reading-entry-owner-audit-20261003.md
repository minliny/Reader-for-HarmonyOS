# Reading entry/prefetch owners: source and integration boundaries

Clean baseline `11b95d3e`; independent `codex/p2-reading-entry-owner-20261003`. No Index, LocalBookDetail, retained reading component tree, RuntimeOwner, Directory/Offline gateways, typography, Native/SDK/HAP or target writes in this lane.

## Prefetch first slice

The actual Index rolling reader-window producer and near-end catalog producer now have `ReadingPrefetchHost` as one domain owner: pending/active/completed work, single drain, latest requested window, content/Runtime/lifecycle admission, readable TOC positions, unchanged two-before/two-after window, completion backoff, refresh cooldown/attempt/inflight and actual append eligibility. Existing `ReadingOfflineGateway` owns materialization and terminal report cleanup; `RemoteReadingFlowGateway`/BookAcquisitionCoordinator owns canonical acquisition. No replacement parser, matcher, queue service, native protocol or cache policy is introduced.

`forRuntime(capturedRuntime)` returns the same owner across Index remounts and refuses a retired Runtime before replacing the cache. `retire()` invalidates optional admissions and pending UI delivery; active actual Gateway work still drains its native leases/reports. New reader admissions share the old drain, avoiding a second concurrent producer. Refresh timestamps are removed only after their original eligibility deadline has actually elapsed and the corresponding native refresh has settled. A future timestamp/backwards clock is retained. Retirement never expires or replaces an unsettled refresh, even when its old presentation predicate is false. P9 retention/performance budgets remain separate; there is no new entry-count cap, LRU policy or timer.

P5 API: `prefetch(session, preferredChapterIndex, lease, mode)` where mode is `reader`, `shelf`, `opportunistic`. Reader owns one latest window; shelf jobs stay independent and incomplete results throw the existing message; opportunistic work preserves its previous non-throwing partial-result semantics. Lease contains only captured UI `isCurrent`, `displayedSession`, current `directory`, pure `projected(entries)`, `refreshed(session)` and `diagnostic(stage,message)` delivery. The Host captures actual Runtime/content/lifecycle, selects and executes work, patches only changed download states while retaining bookmark/level/navigability fields, and protects state from observer/diagnostic exceptions. Page callbacks must capture navigation/session identity; they must not fetch fresh identity in old callbacks.

`noteCatalogRefresh(identity,lastCheckAt)` consumes the original seconds timestamp; `nearEnd(session,index)` preserves the three-chapter threshold, and `refreshNearEnd(session,lease)` performs actual forced acquisition and existing `canAppendRemoteReadingCatalog`. Changed prior chapter requests require reopen; they never remount or replace the retained reader. The accepted refresh timestamp is independent of UI callback exceptions. Original ten-minute success and thirty-second failed-attempt intervals remain.

P5 removes `ReadingWindowPrefetchIntent`, reader queue/task/latestKey fields, catalog timestamp/attempt/inflight maps and readable-Toc index fields from Index. Existing wrappers may only capture UI admission/DTO projection and call this owner; they may not keep a second window-selection/drain or near-end eligibility algorithm. `installRemoteReadingSession` may drop its old readable-order bookkeeping; Host derives it from the actual admitted TOC array. Reader commit/directory/BookshelfHost real callers must be connected before family closure.

`node tools/test-reading-prefetch-host.mjs` executes the full actual owner plus full Offline/Remote gateways through controlled Core/native IO: 1370 chapters/eight page admissions become one five-chapter window; latest window coalescing; real materialization lease draining on retirement; content revision and immutable row updates retaining bookmarks; thirty-second retry; independent per-book work; unknown indexes; real acquisition/inflight dedup and append eligibility; persisted last-check/cooldown; observer/diagnostic isolation; late catalog retirement; expired-settled deadline pruning with future-clock and native-inflight retention. A mutated actual lifecycle admission reproduces late delivery. This is not Index SDK, native timing, platform memory, target or visual proof; P5 owns actual Index integration and old implementation deletion.

## ReadingEntry complete producer slice

`ReadingEntryHost` owns the real entry journey: local TOC admission; selected/cached/supplied/group remote acquisition; candidate readability; source-name and exact shelf reconciliation; semantic session/readability admission; position-qualified body probe; stale-cache recovery; optional warm refresh; detail-projection queue; persisted shelf and visible-window preparation admission. It uses the existing BookAcquisitionCoordinator and ReadingEntryPreparation for canonical acquisition/native scheduling, existing remote position and content validators, and the shared ReaderDirectoryHost for bookmarks. It does not own navigation, native AlertDialog scheduling, physical reader readiness/chapter state, retained ArkUI trees, appearance persistence or canonical storage. This is a bounded Reader domain owner rather than a global executor/event bus.

The feature-local `forRuntime(runtime)` is shared across Index remounts. A retired lookup cannot replace the successor; `retire()` removes only presentation/admission leases. Accepted Core work settles through the original coordinator/Gateways. Every body, projection, directory, background and native-choice delivery captures scope, session generation, actual Runtime, lease and relevant revision. A same-book/same-catalog re-entry still rejects the old body generation. The shared Directory mutation/read mutex owns bookmark projection; download status reads retain the latest bookmark fields before that one canonical bookmark read. No second bookmark merger or downloader is introduced.

The finite `ReadingEntrySnapshot` carries `scopeId`, `sessionGeneration`, book, seed, TOC, session, shelf presence, loading message, content verdict, candidate-active/failed and optional background error. Page projection is DTO assignment only; it must not run a second semantic install/probe. An unprepared catalog remains `verifying`; only an actual position-qualified prepared chapter or exact Core schema-2 verification with matching identity/versions/current revision can establish readability. A Core metadata verdict is never turned into a fabricated reusable body. Background/read/name failures retain already admitted content; failed candidate admission suppresses notification-driven automatic retries. Full shelf snapshots can establish presence, while search fallback requires an actual exact shelf absence read. Explicit shelf changes are guarded by the Bookshelf operation generation on every later independent publication, not merely the membership request callback.

### Exact consumer interface

| Entry interface | Required page contract | Producer and result |
| --- | --- | --- |
| `openLocal(selection, lease, resumeImmediately?)` | Perform original route change, then supply captured Runtime/navigation/entity/mounted lease. | Synchronously publishes selected local DTO; explicit detail performs real TOC/download/bookmark admission. Shelf resume performs no detail IO. |
| `openRemote(input, lease)` | Supply original seed/name, known shelf presence, search/fallback candidates, validated/retained session and resume flags. Do not infer absence from a filtered list. | Executes actual coordinator admission, single body-verdict producer, partial catalog/failure preservation, optional background refresh and shared directory projection. Remote shelf resume preserves actual Runtime preparation intent without detail IO. |
| `bindReader(book, session, toc, inShelf, lease)` | Called at the real physical reader/source-switch boundary using the captured new reader lease. | Rebinds this presentation and validates exact session identity; no detail acquisition, route change or tree reconstruction. |
| `acceptSession(session, readableRevision?, projection?)` | Pass actual canonical session/qualified Core projection; no page-side proof algorithm. | Single semantic session/readability state owner. |
| `readerSessionReady(session)` | Actual ReaderShell event must first pass captured reader tuple. Page keeps physical chapter/readiness milestones. | Updates catalog/book/loading projection; false for foreign/retired admission. |
| `deferredDirectoryProjection()` | Capture closure at the real reader-ready boundary, invoke on the original post-frame milestone. | Closure checks original scope/session generation and cannot borrow a replacement reader. |
| `probe(scopeId, preferredIndex?, positionContext?)` | Use the current snapshot scope and actual persisted position context. Page only selects route after returned qualification. | Exact-resume probes one requested chapter; only a new-book admission may skip up to the original three leading blank chapters. Unknown resume indexes are not clamped. |
| `refreshProjection()` | Invoke for admitted detail notifications only; `projectionAllowed` represents original detail-visible/not-reading/not-source-switch state. | One active read and one latest pending intent, actual coordinator revision recheck, canonical metadata/stale readmission and background-error preservation. |
| `preparePersisted(context, shared?)` / `prepareVisible(books, context, shared?)` / `preparationVisibilityChanged(context, shared?)` | Supply captured page identity, live foreground/shelf/reader/settings facts and current complete projection revision. Shared seed promise must belong to exact Runtime/revision. | Calls the existing Runtime preparation owner and its real idle/concurrency/budget rules. Fallback is one actual all-filter membership projection with revision admission; visible mode retains original optional appearance warm-up. |

`ReadingEntryLease` contains only `isCurrent`, `projectionAllowed`, current directory/offline generation, `membership`, `changed`, `cacheDecision`, `notice`, `refreshShelf` and diagnostic effects. `membership()` is a projection of the existing BookshelfOperation owner's generation/busy lock and current page detail presence; it must not create another membership/write owner. `cacheDecision(error,current)` is the existing native AlertDialog seam: callbacks capture this original `current`, reject retired choices, and return the actual user decision. The Host performs the real forced read and the original two coordinator-revision CAS handoff. Dialog failure/retirement cannot cancel or replay progress and cannot set readable.

### Required Index deletion and integration

P5 owns actual Index/ReaderShell integration. Replace these original producers with thin captured admission/effect wrappers; method names identify behavior despite line-number drift:

| Original Index responsibility | Replacement / retained boundary |
| --- | --- |
| `openLocalBookDetail` local TOC/error/download/bookmark IO | `openLocal`; Index keeps detail route and physical page DTO. |
| `openRemoteBookDetail`, candidate fallback/catalog callbacks, source-name and shelf reads | `openRemote`; Index passes selected metadata and real explicit membership generation. Delete local candidate transaction/state algorithm. |
| `refreshRemoteBookDetailInBackground` | Host warm-refresh path; Index only projects current snapshot. |
| `refreshDetailAcquisitionProjection` and pending/active request fields | `refreshProjection`; delete page queue/revision/reacquire/semantic merge implementation. |
| `installRemoteReadingSession`, readable revision and body probe generation | `acceptSession`/`readerSessionReady`/`probe`; remove duplicated evidence/readability logic and old generation fields after all consumers use owner. |
| `requestRemoteContentProbe`, cached-body recovery, forced-refresh semantic handoff | `probe` plus captured native `cacheDecision`; retain native host scheduling only. The old unused notice-generation field is not a new owner field. |
| `preparePersistedShelfBooks`, `prepareVisibleReadingBooks`, foreground/viewport preparation wrappers | Host context/admission API; retain the existing Runtime ReadingEntryPreparation, its actual idle/budgets and full-revision shared seeds. |
| Reader session-ready / post-frame directory / entry resume | `readerSessionReady`, `deferredDirectoryProjection`, `bindReader`; Index retains physical ready generation, actual active chapter, route and immutable reader identity. |
| Rolling prefetch and near-end refresh | Existing `ReadingPrefetchHost`; no duplicated queue/maps/append eligibility. |

SourceSwitch canonical ACK is a separate exact proof already delivered in `source-switch-reader-finalization-ack-20261003.md`: Index may use only `ReadingCommit.sourceSwitchTransactionId` originating from the actual qualified canonical finalize ACK.
