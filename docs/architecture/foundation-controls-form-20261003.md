# JSON/RSS form control migration (2026-10-03)

Current UI is the baseline. This change moves five authored control structures (JSON local action + URL field, RSS editor save + field, RSS management import/export action) into the actual ReaderButton/ReaderFormField implementations. Business draft, validation, request ownership, recovery, close and callbacks remain on their original owners.

Three named button variants retain the original 44/r8 form label, 44/r8 busy save and 36/r8 document action. Border remains omitted for all three; JSON/document opacity remains AUTO; busy save retains 0.62 disabled opacity. Two field variants retain 44/r8/pad12: NotoSans body on paper with native placeholder AUTO, and Inter URL on field surface with muted placeholder. All five physical text attributes and every AUTO omission are verified against immutable original tuples. URL keyboard submit alone is installed; plain RSS fields retain native submit AUTO.

The new field onSubmit callback is construction-time in V1, delegates the current parent draft owner, and is guarded by live mounted/editable state. The shared native control is never remounted as a whole page. Current @Prop changes update retained actors; old physical clicks/keyboard events use current enabled state. SDK foundation auto resolution is independently tested with an actual RSS caller omitting explicit dependencies: actual native text, production commit/lifecycle, disabled propagation and old callback rejection all run.

Proofs: test-foundation-controls-shared, test-json-import-dialog-real, test-rss-editor-operation-recovery, test-rss-management-typography, test-typography-carrier-successors, conventional source/SDK tuple suites. Producer/spec/consumer edges are registered from actual SDK AST; original 100 private budgets are unchanged. Typography relocation includes the actual RSS build→saveAction edge, not a name-based exception. These are source/SDK/local contract results, not signed whole-application ArkTS, HAP or device/visual acceptance.
