# P7 current popup motion admission

Baseline `ea91bef8`, independent `codex/p4-final-ui-consumers-20261003`. Code-side audit found that ReaderFullDirectory's next-turn expansion did not recheck reduceMotion, and ReaderSelectPanel / BookshelfMoreMenu did not react to a real Prop change while their close animation was pending. Actual production-method negatives reproduced both. Existing reading-turn retirement did not cover these consumers.

The original three component owners retain their structure, dimensions, motion registry and business callbacks. Each now observes the actual reduceMotion Prop. Enabling it retires the old animation generation and applies the existing endpoint with zero duration. A pending close retains its captured original completion and delivers it once; old finish callbacks, unmount and a replaced selection identity cannot publish it again. Business actions already committed are never cancelled or repeated. Enabling animation again does not replay an old action. The directory's scheduled expansion independently repeats current admission before starting.

`test-popup-reduce-motion-lifecycle.mjs` uses the installed SDK component transform and actual property runtime classes. Only native animation delivery and the platform next-turn scheduler are controlled. It verifies actual Prop reset / Watch, the three current owners, old completion negatives, selection replacement, unmount and a missing-Watch mutation. This is SDK/method evidence, not compositor cancellation, device pixels or target acceptance. Existing geometry, selector/menu and reading-motion regressions remain required.
