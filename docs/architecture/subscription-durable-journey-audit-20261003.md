# Subscription original journey: implemented code candidate

Baseline: Host f9092184; Core 66d4142f. Required SC01/WF-F07 subscription original import → update timestamp previously had no durable full journey. A dropped Source/RSS ACK could be treated as ordinary failure, continue importing, or disappear with an Orchestrator reconstruction. A timestamp retry could use a new Date.now() rather than the accepted original tuple.

The existing Rules mutation authority now accepts a finite subscription variant. Its sole Atomic record keeps the original admitted source DTOs or RSS/bundle JSON, one metadata timestamp, current exact ID/sequence, current cursor, original item admission failures and qualified settled Core receipts. Source admission delegates the existing JSON/URL/shape validation; original Source import, RSS parser/merge, replacement bundle and subscription DTOs remain authoritative. No second generic executor, global error bus, parser, queue or ledger is introduced.

Each item uses the same Core rules head. Source single-row publication, the original RSS import domain and Chinese conversion singleton/local position updates can carry the original receipt in their existing SQLite transaction/memory lock. RSS prepared publication compares only its original subscription/read-record/config/entry-cache domain under that transaction; it preserves newer unrelated app rows and RSS favorites. Original Legacy APIs remain compatible. New subscription/conversion capabilities fail closed on an older Core before creating new intent; protocol v1, schema34 and ABI remain unchanged.

Unknown current ACK stops all later items and the metadata write. Matching list rows never confirm it. Pure recovery queries the original fixed tuple and does not redownload/replay/advance the journey. Explicit recovery may reapply only the same ID/full DTO when head is exactly its predecessor. Known current receipt permits atomically retaining its proof and assigning the next fixed tuple; next dispatch waits for actual Atomic ACK. A lost local advance ACK preserves the accepted successor and the qualified predecessor proof, permitting re-persistence of the same successor. Higher head or corrupt/different receipt remains blocked.

Definite original Source item rejection continues the original partial import semantics. Local invalid entries remain item failures. A wholly failed Source import does not save the subscription timestamp. RSS/bundle rejection and metadata rejection terminate that journey without pretending the timestamp was saved. The projection separates current cursor, imported confirmed steps, failed items and metadata confirmation; complete import with a failed list refresh remains a confirmed write plus failed refresh. Drafts are retained. An old Orchestrator/session callback cannot start a new accepted journey or clear successor authority.

Actual code proofs: `test-rule-subscription-durable-journey.mjs` exercises whole real Gateway/Owner/Atomic adapter/Orchestrator via Node and installed SDK compiler against cold SQLite CLI: partial success, per-item exact rejection, Source/RSS/bundle dropped ACK, no side effects on pure reopen, same-ID explicit retry, fixed timestamp, timestamp ACK loss, higher-head blocking, Atomic advance ACK loss and pre-dispatch retirement. Original nine-rule durable/consumer gates are retained. This is code/SDK/CLI evidence. OS AtomicFile rename/fsync acknowledgement, HAP provenance and target behavior are separate; no HAP/VM used here.

Rollback: preserve any accepted intent and Core local head. Do not downgrade to a Native that ignores the new variants/capabilities while such intent remains. The current full payload scales with the original source-document entry limit (5000); actual file IO/latency/RAM budgets remain P9 target evidence, not a newly invented byte cap.
