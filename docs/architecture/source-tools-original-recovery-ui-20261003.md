# SourceTools original recovery consumer (2026-10-03)

SourceToolsPage now consumes the existing finite RulesMutationSnapshot original fact supplied by SourceToolsOrchestrator. A blocked original takes precedence in the existing status surface and disables new source writes, editor entry, draft replacement, save and cancel. Read-only checking, selection, export and debugging retain their original admission. A small batch-controls key includes write admission; catalog data-source reprojection tracks it without remounting the catalog/page. The normal font, border, padding, geometry and draft values stay unchanged.

The existing compact ReaderRecoveryAction implementation supplies two distinct controls. “核对原操作回执” passes the original generation to onReconcile and performs a pure exact-receipt read. “继续原操作” is available only when the owner qualifies canRetryOriginal; confirmed Core success with unfinished Host cleanup instead says “继续原清理”. The latter calls the new onContinueOriginal(generation) callback, never starts a replacement draft or new identity. Both controls disable while the original/page is busy.

The recovery subtree is keyed by exact generation, operation ID, confirmation, write stage and admission. Its physical callbacks capture that identity and check mounted/current facts before forwarding. An old action cannot borrow new Props or a later generation, including within the same retained Page. Index supplies the existing exact Runtime/navigation/presentation guard; that wiring remains the Index writer's separate change.

It covers lost ACK before and after the Core write, pure cold-open/reconcile, same-ID explicit continuation, committed-but-cookie-cleanup failure with zero repeated Core writes, retained prior physical actions, busy actions and unmount. The original SourceTools receipt suite, cold-owner suite, whole text-family SDK and unchanged style budgets remain required.
