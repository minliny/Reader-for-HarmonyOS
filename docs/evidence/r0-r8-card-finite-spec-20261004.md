The shipping ReaderCard exposed arbitrary bg/cardBorder/radius. Its six callers used two actual physical tuples, but the actual producer gate accepted a synthetic SyncPage radius 99 with an unchanged call count. The preserved pre-fix negative is tools/fixtures/reader-card-illegal-input-before.json (frozen ad419847 source; no production mutation).

This change removes all three arbitrary appearance inputs. settings-category and sync-config share the same standard spec object; four sync-status callers share the existing r13 spec. cardWidth remains page measurement (positive width, otherwise 100%), content remains the actual Builder slot. The maximum width and border remain the actual current ReaderTokens values. No text/body geometry, business callback, recovery, or native input changes are intended.

Six real calls: CategorySection.build and SyncPage.webdavSection/manualActionsSection/autoBackupSection/emptyState/historyRow. The SDK differential suite mounts these original and current production Builders and actual old/current ReaderCard, compares every native outer-card attribute, checks retained Prop updates, shared-spec propagation and variant isolation. It also verifies removal of the old inputs and rejects literal99, unknown variants and caller appearance overrides through the actual producer gate.

ReaderCard keeps its unique immutable row in the original100 private-budget registry (backgroundColor1); that row is historical budget only. Its exact finite producer, spec implementation, six consumers, public interface and SDK/removal proofs are independently verified. The additional registration mode is restricted to that exact original ReaderCard file/row/id; other paths cannot gain it. No budget increase and no common-directory wildcard.

Evidence tiers: production source, Node contract and installed SDK-emitted Builder/native call proof. HAP/native scheduling, device pixels, visual and user acceptance are separate and are not claimed here.
