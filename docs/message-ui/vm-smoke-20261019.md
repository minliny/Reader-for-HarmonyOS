### F1代码侧定位

`BookshelfSettingsPage.ets:47-55` 从CredentialStore取到已有canonical时会跳过 `loadMode()`，但页面显示准入在167行依赖另一份 `viewModeSnapshot.canonical`。`BookshelfViewModeHost.ts:23,35` 的初始snapshot为undefined且 `current()` 直接返回它；因此“Store已有值、Host未加载”能进入不可重试的“尚未读取”分支。这是与VM现象一致的确定代码路径；未添加运行时探针证明本次实例内部值。修复需统一初始化与渲染所用canonical，保留原receipt/待确认状态；应补Store已有值且Host首次进入的生命周期回归。本轮只记录定位，未修改生产代码或重新构建。
