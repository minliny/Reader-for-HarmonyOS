- `ReaderPageState` 提供原插图/原动作 slot、局部无内边距和动作准入，默认视觉不改。搜索、阅读目录、正文搜索初次状态及书签等待接入；已有结果和滚动/定位主体保留，不把局部失败替换成整页错误。
- 目录层级规则投影在 `BookDirectoryPage` 现有 `overlayContent` 顶部承载；核对、继续及真实 busy 在同一通知。编辑器首次打开后收起仅隐藏布局，保持未决原操作宿主；切书、格式变化和页面退场使旧投影/动作失效。已确认写入后的目录刷新失败为短反馈，原刷新入口保留。
- 独立目录原书签/离线通知也移到现有 overlay，避免通知撑大页头。提示在下载 popup 期间避让，原业务 owner 与回调不变。
- 下载确认框外框接入 `ReaderDialogSurface` 的 `download-confirmation` 有限变体，保持306vp宽、17vp内距、12vp圆角、原标题/正文/按钮及溢出滚动；不重做动作或关闭语义。
- 受控开发规则和 [消息框架规范](FRAMEWORK.md) 明确要求所有新增/修改消息按类别接入。入口清单和显式检查仅服务消息接线，不加入默认构建/CI/完整门禁。

## 实施中发现的问题

1. 入口清单的官方ETS AST只读提取发现本轮迁移中的`SearchPage.ets`约1336行存在语法诊断，首项为`; expected`并伴随后续连锁诊断。原因是三个BuilderParam箭头直接内嵌ArkUI DSL，被ETS当普通TS解析；已改为调用具名`@Builder`，保留原动作树。修改者同口径只读解析诊断归零；这只证明语法，正式定向结果另记，不扩跑套件。
2. 同步开发规则前只读确认既有27个投影只有本次受控`AGENTS.md`漂移，`sync-workspace --check`按预期拒绝旧投影。随后沿原`--write`入口只更新这一文件，其他26个投影未修改；不是完整门禁或业务失败。
3. 收尾源码复核发现独立目录和全目录父页与新导航子层都可能渲染初始空目录状态。已让父页明确拥有首次空内容提示，子层仅在已有条目或导航已激活时显示其加载状态，避免重复提示/重试；已有结果的局部状态仍保留。
4. 顶部通知避让下载popup若直接卸载，关闭后会重建读回失败的去重集合。已改为临时隐藏并保持挂载，原通知和一次反馈身份保留。
5. 书架被阅读覆盖时仍保留挂载，不能只依赖mounted允许Toast。已为书架内容/外壳加入明确`feedbackEnabled`；公共适配层统一用既有`readerAppForeground`事实抑制后台短反馈，不引入新的业务状态。
6. 首次入口检查124/124组通过；19项定向检查18项通过，唯一失败是验证脚本把BookDirectoryPage另一个漫画宿主也当成标准目录的“唯一初始状态”检查。源码目标是`standardContent`与FullDirectoryPanel的`chapterList`，漫画分支本身由子层/自身fallback单独承接。保留首次FAIL回执，验证脚本改为AST按目标Builder筛选，维持同样三个状态断言，再跑同一19项，不扩大套件或删减失败项。
7. 源码收尾复核发现目录规则`onApplied`只递增`rulesRevision`，实际刷新由`ReaderDirectoryNavigationSurface`异步读取；原先仅捕获同步回调异常的短反馈不能覆盖这条路径。将已有结果的实际异步失败接到统一短反馈，保留原列表及重试动作；无可用结果仍由页面状态承接，能力不支持的平面回退不冒充读取失败。该问题不涉及重派规则写入。
8. 短反馈适配新增短时去重后，常驻宿主不能仅在组件卸载时清理：Index在既有导航/路由/前台退役点、实际换章时重置；小说阅读在统一章节选择/阅读窗口失效点重置；漫画后台准备失败沿用manifest身份作为key，避免新章节被旧同文案抑制。仅复用已有状态和身份，不创建另一套业务代次。
