# Reader 跨平台界面参考

本目录是以非鸿蒙原生增强主线的**已提交版本**整理的 UI、页面逻辑及交互交接入口。用户于 2026-10-20 指定：鸿蒙原生特性引入前的通用样式作为全平台兼容参考；本轮先收敛非原生分支当前提交，仍在进行的 UI 优化另行保留。

这里整理已有设计、合同与实现，不新增产品设计，不将正在开发的鸿蒙特性纳入 iOS 必须复刻的范围。`REFERENCE_GAP` 表示该版本资料尚不足以独立说明某项行为，不表示功能未实现，也不形成另一份开发待办。

## 材料效力与冲突处理

1. 本轮版本选择及用户已明确的产品要求确定复刻范围。鸿蒙原生增强、自选系统外观以及未提交优化不自动改变通用基准。
2. 所选版本的产品范围、消息分类与专项行为合同约束实现；颜色和几何有共同 JSON 来源时，读取该 JSON 的所选提交。生成文件用于核对实际消费，不成为第二个可编辑来源。
3. 当前生产实现用于补出合同未展开的具体参数和调用关系。文档中将其标为实现参照；发现与明确合同相冲突时保留差异，不能默认复制缺陷或静默改变设计。
4. 历史实景只证明当时看见的画面和动作。已批准设计的精确归档只在其批准范围内有效，不能因目录名含 `approved` 而把全部历史页面、状态和参数升级为当前规格。
5. 历史计划、执行日志、测试 PASS、构建或安装结果分别保留原证据层，不据此填充新平台画面、运行态或用户验收。

相对链接便于在正常 Reader 多仓目录中定位文件；链接指向的工作树内容可能继续变化。发生疑问时按 `BASELINE.json` 的仓库与提交读取原字节。例如：

```sh
git -C Reader-for-HarmonyOS show 33f7c7b21474a76a042ebda911c5f0ff2d73cf54:entry/src/main/ets/features/common/ProductMotionTiming.ts
git -C Reader-UI show 95366cd93775ea0ad3ecbc0f60e8882717f93169:theme/registry.json
```

上述命令在 Reader 工作区根目录执行，只读取版本对象，不切换分支、不覆盖工作树，也不执行构建或门禁。

## 资料缺口如何阅读

三个分册将问题限定在相应合同旁，主要包括：

- 全部嵌套入口的父级与状态保留组合尚未形成一张完整冻结表；书源筛选与工具草稿的部分退出规则仍未明确。
- 若干运行/结果态缺少与所选版本绑定的视觉参照；历史未采集不等于生产未实现。
- 部分动效依赖平台弹簧、原生滚动或系统窗口；没有依据的内部曲线、容差和平台替代选择不能补写成既定参数。
- iOS 的实际页面、生命周期与渲染尚未完成，不能用 Core wrapper、历史 Swift 示例或浏览器演示替代。

这些是基线交接的限制说明。开发排期仍只维护在工作区唯一 `DEVELOPMENT_BACKLOG.md`；本目录不登记另一套任务状态，不因资料收敛触发代码修复、全量测试或设备取证。

## 后续 UI 优化怎样进入参考

正在进行的 UI 优化保持原分支、原工作树和所有者。其结果提交后，按实际变更选择是否更新这份通用参考：

1. 记录新提交及涉及的页面、组件、共同规格和资产，明确属于通用优化还是平台专属增强。
2. 对照上一份固定输入，只更新受影响的合同、参数、来源与证据边界。
3. 同步三个分册及输入清单的版本，保留 Git 中此前参考，不通过重拍哈希将未经审查的差异自动认可。
4. 源码整理、产品实现、包、设备效果和用户验收分别记录；某一层更新不代替其他层。

本次交付是文档整理与来源绑定。只核查新增文档链接、选定输入身份、跨仓派生来源及文档差异，不执行产品门禁、生成器、构建、签名或设备操作。
